# 間取り図 → 3D 户型

产出：`plans/<id>.json`（户型数据）+ 一个私有 Artifact 网页（单文件版），并推到用户的仓库。

## 0. 准备

1. 拿代码：`git clone https://github.com/WuYan-GoEN/floorplan-3d`（用户的 fork）。clone 失败就先 `mcp__claude-code-remote__add_repo` 加仓库再试；仍不行，告诉用户需要先在 GitHub 上 fork `wy51ai/floorplan-3d` 并合入本改造。不要用 API 创建 fork（会被代理拒绝）。
2. 读 `PLAN_FORMAT.md` 了解数据格式；`plans/3gou-4ldk.json` 是完整的两层示例，照着写最快。
3. 记下物件信息：建物面積（核对用）、各房间帖数、价格等。地址、门牌**不要**写进数据（仓库可能公开），`id` 用 `3gou-4ldk` 这种不含地名的写法。

## 1. 量墙线

1. 把图里每一层的范围找出来（原图像素），裁剪放大看清楚。
2. `python3 tools/wall_lines.py 图 x0 y0 x1 y1` 得到竖墙 / 横墙的像素位置和连续段；段与段之间的空缺 = 门、窗、开口。
3. 定比例：日本住宅按 **910mm 模数**（1 格 = 910×910 ≈ 0.828㎡，1 帖 = 2 格）。用外墙总长或已知帖数的方正房间（4.5 帖 = 3×3 格）算出每格多少像素，再把所有墙线换成 mm，**对齐到 455mm**（半格）。
4. 多层对齐：各层不一定上沿对齐。用楼梯位置（上下层楼梯必须重叠）和阳台（一般正好压在下层屋顶上）确定上层相对下层的偏移，全部换到 1F 坐标系。

## 2. 读图惯例

- 门：门扇画在**打开**位置（垂直于墙），弧线从门扇尖端扫到对面门框；门扇贴墙的那一端是铰链。`swing` = 门扇所在一侧。
- 墙外侧的小三角 = 窗（多为縦すべり出し窓）；墙上带「+」的双线 = 引き違い推拉门窗；落地到地面的大窗（通阳台、庭院）`sill:0`。
- 浴室常是折叠门；收纳、クローゼット的门用 `slide`。
- 楼梯：U 形折返楼梯拐角常是 6 级 30° 斜踏步。下层只画到剖切线（下段 + 一半斜踏步，`show3d:true`）；上层画全部踏步（`show3d:false`）并用 `voids` 标楼梯井、加 `low` 栏杆。层高约 2900mm，`rise ≈ 2900 / 踏步数+1`。
- 门廊、阳台 `counted:false`；阳台四周用 `low` 墙当栏杆。
- 图上画的家具也放进 `furniture`，方便判断尺寸。

## 3. 照片怎么用

房间照片只用来**确认**：窗的位置和高低、门的开向、地板颜色（选 `mat`）、有没有吊柜等。不要根据照片改墙体尺寸，照片有透视变形。照片和图纸对不上时，在回复里点出来让用户确认。

## 4. 核对（必做）

1. `python3 tools/check_plan.py plans/<id>.json <建物面積>`：全部楼层合计应与建物面積相差 1% 以内；每个房间的帖数应与图上标注接近（±0.3 帖）。对不上就回去找错的墙线，不要硬凑。
2. 有浏览器时截图看 2D/3D 各层（Playwright 的 Chromium 在 `/opt/pw-browsers`；若 cdn.jsdelivr.net 被拦，`npm i three@0.160.0` 后用 `page.route` 把 three 的 CDN 请求指到本地文件），和原图逐层对比门窗位置。

## 5. 交付

1. 写入 `plans/<id>.json`，在 `plans/index.json` 的 `plans` 里加一条，`default` 改成新物件。
2. 提交并推到 `WuYan-GoEN/floorplan-3d`（提交信息写物件名，不写地址）。
3. `python3 tools/build_single.py plans/<id>.json <id>.html`，把这个 HTML 用 Artifact 发布成私有页面，用户手机上直接打开。
4. 回复里写清楚：精度大约 ±10–20cm，靠近临界的家具（余量 <10cm）要现场量；哪些地方是推测的（窗高、门开向等）。
